# 等离子体文献系统 · 接口设计文档

配套数据库见 `schema.sql`（SQLite，`sqlite3 plasma.db < schema.sql` 即可建库并写入 6 本白名单期刊）。

## 总览

系统分两层，异步解耦：

- **确定性检索层**：定时调用学术元数据 API（Crossref / OpenAlex / arXiv + Unpaywall），按白名单 ISSN + 关键词 + 日期增量抓取元数据入库，后台跑，与用户操作无关。
- **大模型理解层**：用户检索→人工下载 PDF→导入后，才触发 GROBID 解析、翻译、RAG、化学库抽取。

建议技术栈：FastAPI + SQLite + APScheduler（调度）+ GROBID（解析）+ Chroma/FAISS（向量库）。前端起步用 Streamlit 最快出可演示界面。

## 通用约定

- 基址：`/api/v1`，请求与响应均为 `application/json`（文件上传除外）。
- 列表统一分页：query 参数 `page`（默认 1）、`page_size`（默认 20）；响应统一为
  `{ "items": [...], "total": <int>, "page": <int>, "page_size": <int> }`。
- 错误统一为 `{ "error": { "code": "...", "message": "..." } }`，配合语义化 HTTP 状态码（400/404/409/422/500）。
- 耗时操作（抓取、解析、翻译、索引、抽取）一律异步：立即返回
  `{ "job_id": <id>, "status": "pending" }`，前端轮询对应资源的状态字段。
- 起步阶段不做鉴权；上线前再在网关或中间件统一加。

## 模块 0 — 系统状态

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 轻量存活探针，返回服务名与 `ok` 状态 |
| GET | `/system/status` | 本地存储、外部能力配置和资源计数 |

响应的 `counts` 至少包含：`journals`、`papers`、`categories`、`paper_categories`、`crawl_jobs`、`documents`、`sections`、`translations`、`chunks`、`reaction_sets`、`reactions`、`reaction_audits`，用于发布验收和本地排障确认核心资源是否已初始化/产出；`paper_categories` 用于确认论文分类映射资产已经落库，`reaction_audits` 用于确认化学库人工复核审计资产已经落库。

响应的 `status_counts` 按既有状态字段汇总工作流分布，至少包含：`crawl_jobs`、`document_parse`、`document_index`、`document_chemistry`、`translations`、`reaction_sets`。每个子对象形如 `{ "failed": 2, "indexed": 5 }`，用于发布后快速判断抓取、解析、索引、翻译、化学抽取或反应集复核是否有失败或积压。

响应的 `runtime` 至少包含：`api_prefix`、`scheduler_enabled`、`scheduler_jobs`、`version`，用于确认当前 API 路径、调度器开关、已注册的 daily/weekly/monthly 抓取计划和部署版本。`scheduler_jobs` 每项包含 `id`、`period`、`trigger`、`schedule`、`timezone`，便于发布后核对 APScheduler 实际周期。

响应的 `storage_health` 至少包含：`data_dir`、`pdf_dir`、`tei_dir`、`translation_dir`、`export_dir`、`database`、`database_parent`、`vector_db_parent`。目录项和 `database` 文件项结构为 `{ "path": "...", "exists": true, "writable": true }`，用于排查新机器目录不存在、SQLite 文件缺失或不可写的问题。`vector_db` 为文件级健康项，结构为 `{ "path": "...", "exists": true, "readable": true, "writable": true, "valid_json": true, "error": null }`；当本地向量索引 JSON 损坏时 `valid_json=false` 且 `error` 给出解析错误，便于在触发 RAG 前排障。

响应的 `config_warnings` 为非阻断配置提示数组，每项结构为 `{ "code": "...", "capability": "...", "message": "..." }`。默认离线模式下缺少 `OPENALEX_MAILTO`、`UNPAYWALL_EMAIL` 或 `LLM_API_KEY` 时只返回 warning，不阻止 API 启动、fixture 导入、smoke check 或本地测试。

`GET /system/status?check_external=true` 会主动检查 GROBID `/api/isalive`，响应的 `external_capabilities.grobid` 包含 `url`、`available`、`status_code`、`error`。`external_capabilities.vector_db_backend` 暴露当前向量库后端，默认 `local-json`；未支持的 backend 会出现在 `config_warnings` 中，并且 RAG 索引/查询会明确失败，避免误判 Chroma/FAISS 已启用。不传 `check_external` 时不访问外部服务，便于离线启动和测试。

## 模块 B — 抓取调度

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/crawl/run` | 手动触发一次抓取（定时任务调用同一逻辑） |
| GET | `/crawl/jobs` | 抓取任务列表 |
| GET | `/crawl/jobs/{id}` | 单次任务状态与统计 |

`POST /crawl/run` 请求体（字段均可选；不传 `journal_ids` 则跑全部 active 期刊）：

```json
{
  "journal_ids": [2, 5],
  "period": "weekly",
  "date_from": "2026-06-01",
  "date_to": "2026-06-23"
}
```

响应 `202`：

```json
{
  "jobs": [
    {
      "job_id": 42,
      "journal_id": 2,
      "period": "weekly",
      "date_from": "2026-06-01",
      "date_to": "2026-06-23",
      "status": "pending"
    }
  ]
}
```

抓取逻辑：按期刊 ISSN 调 OpenAlex/Crossref 拉指定日期段的 works → 字段归一化（OpenAlex `abstract_inverted_index` 会还原为普通摘要文本，Crossref JATS/HTML 摘要会清理为纯文本）→ 关键词布尔过滤 → 写入 `papers`（DOI 去重，命中即更新；无 DOI 时用 `dedupe_key` 做保守去重）→ 逐条调 Unpaywall 补 `oa_pdf_url` → 触发分类。全程记录到 `crawl_jobs`，下次以最近成功的 `date_to` 做增量起点。OpenAlex 返回空列表或临时异常时会尝试 Crossref fallback；如果 fallback 成功，任务仍为 `success`，并在 `crawl_jobs.error` 记录 fallback 诊断信息。

OpenAlex/Crossref 请求受 `.env` 中 `ACADEMIC_API_MAX_PAGES`、`ACADEMIC_API_MAX_RETRIES`、`ACADEMIC_API_RETRY_BACKOFF_SECONDS`、`ACADEMIC_API_TIMEOUT_SECONDS` 控制；Unpaywall 请求受 `UNPAYWALL_API_MAX_RETRIES`、`UNPAYWALL_API_RETRY_BACKOFF_SECONDS`、`UNPAYWALL_API_TIMEOUT_SECONDS` 控制。遇到 429 时优先尊重 `Retry-After`，否则按 backoff 退避。`OPENALEX_MAILTO` 会写入 OpenAlex polite pool 参数和 Crossref User-Agent。

`crawl_jobs` 统计字段：`papers_found` 为元数据 API 返回总量，`papers_filtered` 为关键词过滤剔除量，`papers_new` 为新增入库量。

`GET /crawl/jobs` 的每个 `items[]` 与 `GET /crawl/jobs/{id}` 除返回 `crawl_jobs` 行字段外，还返回：

- `journal`：当前任务对应期刊摘要，包含 `id`、`name`、`issn_print`、`issn_electronic`、`active`。
- `diagnostics`：排障用结构化统计，包含 `journal_id`、`journal_name`、`period`、`date_from`、`date_to`、`status`、`papers_found`、`papers_filtered`、`papers_new`、`papers_accepted`、`papers_existing`、`error`。其中 `papers_accepted = papers_found - papers_filtered`，用于区分“元数据源无结果”和“关键词过滤剔除过多”；`papers_existing = papers_accepted - papers_new`，用于判断已抓到但只是更新了既有记录的情况。

## 模块 C — 文献检索（核心）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/papers` | 检索（见下方参数） |
| GET | `/papers/{id}` | 文献详情 |
| POST | `/papers/{id}/resolve-oa` | 用 Unpaywall 重新解析 OA 链接 |
| POST | `/papers/{id}/classify` | 触发 LLM 分类 |
| PUT | `/papers/{id}/categories` | 人工覆盖分类 |

`GET /papers` query 参数：`q`（全文检索标题+摘要，走 FTS5）、`category`（slug）、`journal_id`、`year_from`、`year_to`、`oa_only`（true 时只返回有 `oa_pdf_url` 的）、`sort`（`date_desc` 默认 / `relevance`）、`page`、`page_size`。

响应示例：

```json
{
  "items": [
    {
      "id": 1287,
      "doi": "10.1088/1361-6595/abxxxx",
      "title": "Global model of an Ar/O2 inductively coupled plasma",
      "journal_name": "Plasma Sources Science and Technology",
      "published_date": "2026-05-12",
      "oa_status": "green",
      "oa_pdf_url": "https://repository.example/...pdf",
      "landing_url": "https://iopscience.iop.org/article/...",
      "source_api": "openalex",
      "dedupe_key": "doi:10.1088/1361-6595/abxxxx",
      "has_doi": true,
      "dedupe_strategy": "doi",
      "categories": ["sources", "chemistry", "methods"],
      "category_details": [
        {
          "id": 1,
          "slug": "sources",
          "name": "放电与等离子体源",
          "confidence": 0.86,
          "method": "auto"
        },
        {
          "id": 2,
          "slug": "chemistry",
          "name": "等离子体化学",
          "confidence": 1.0,
          "method": "manual"
        }
      ]
    }
  ],
  "total": 43, "page": 1, "page_size": 20
}
```

`source_api`、`dedupe_key`、`has_doi`、`dedupe_strategy` 用于审计保守去重：有 DOI 时 `dedupe_strategy=doi`；无 DOI 文献会用 `no-doi:<sha256>` 形式的 `dedupe_key` 并返回 `dedupe_strategy=no_doi_fingerprint`，避免同一来源页/标题/日期重复入库，同时让前端和排障工具能解释合并原因。

`categories` 保留为向后兼容的 slug 列表；`category_details` 返回同一批分类的完整结构，包含分类 `id`、`slug`、`name`、`confidence` 和 `method`（`auto` 或 `manual`），用于前端展示置信度和人工覆盖状态。

`PUT /papers/{id}/categories` 请求体：`{ "category_ids": [1, 2, 6], "method": "manual" }`。

## 模块 E — 文档导入与解析

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/documents` | 上传 PDF（multipart：`file`，可选 `paper_id`） |
| GET | `/documents` | 已导入文档列表 |
| GET | `/documents/{id}` | 详情（含 `parse_status`） |
| POST | `/documents/{id}/parse` | 触发 GROBID 解析 |
| GET | `/documents/{id}/sections` | 解析出的结构化章节 |

`GET /documents` 与 `GET /documents/{id}/sections` 均支持 `page`、`page_size`，响应遵循统一列表结构。

`POST /documents`、`GET /documents`、`GET /documents/{id}` 返回的 document 对象除 `documents` 行字段外，还包含 `paper`：若 `paper_id` 已关联论文，`paper` 为 `{id,doi,title,journal_name,published_date}`；未关联时为 `null`。重复上传返回的 `409 document_duplicate` payload 中 `document` 也遵循同一结构。

`POST /documents/{id}/parse` 响应 `202`：

```json
{
  "job_id": 42,
  "document_id": 42,
  "parse_status": "parsing",
  "status": "pending"
}
```

上传时按 `file_hash` 去重；命中已有则直接返回旧记录（409 + 已有资源）。解析完成后 `parse_status=parsed`，章节写入 `sections`，TEI 落盘到 `tei_path`。重新解析同一文档时会清理旧 `chunks`、向量索引、翻译和化学抽取结果，并将 `index_status` 置回 `not_indexed`、`chemistry_status` 置回 `not_extracted`，避免旧 section 派生产物继续被使用。TEI 解析覆盖 `abstract`、正文 `body`、`table`、`figure_caption`、`reference`。GROBID 不可用或返回异常但本地文本 fallback 成功时，`parse_status` 仍为 `parsed`，`parse_error` 记录降级原因；完全失败时 `parse_status=failed` 且 `parse_error` 记录失败原因。

## 模块 F — 翻译

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/documents/{id}/translate` | 触发翻译，body `{ "target_lang": "zh" }` |
| GET | `/documents/{id}/translation` | 取翻译结果/状态 |

`POST /documents/{id}/translate` 响应 `202`：

```json
{
  "job_id": 17,
  "document_id": 42,
  "target_lang": "zh",
  "status": "pending"
}
```

实现要点：翻译前先把公式区域（行内 `$...$` 与行间公式）替换成不可翻译占位符（如 `<EQ_007>`），只送纯文字给模型，译完按占位符回填。未配置 `LLM_API_KEY` 时使用本地 echo adapter，明确保留原文；配置 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL` 后使用 OpenAI-compatible `/chat/completions` adapter。翻译任务创建后写入 `translations`，成功为 `status=done + output_path`，失败为 `status=failed + error`，例如未解析文档会记录 `document has no parsed sections`。

## 模块 G — RAG 知识库

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/documents/{id}/index` | 分块 + 向量化入库 |
| GET | `/documents/{id}/chunks` | 查看索引状态与 chunk/vector 映射 |
| POST | `/rag/query` | 提问检索 |

`POST /documents/{id}/index` 响应 `202`：

```json
{
  "job_id": 42,
  "document_id": 42,
  "index_status": "indexing",
  "status": "pending"
}
```

分块按 `sections` 章节边界切；每个 chunk 写入 `chunks`，并同步写入 `VECTOR_DB_PATH` 指向的本地 JSON vector store，向量记录保留 `chunk_id`/`section_id` 回链，并记录 `embedding_model` 与 `vector_db_backend` 便于排障。重建同一文档索引时会先替换该文档旧向量，避免 RAG 命中已删除 chunk。`GET /documents/{id}/chunks` 支持 `page`、`page_size`，返回 `{items,total,page,page_size,indexed,index_status,index_error}`，每个 item 含 `section_title` 与 `vector_id`，供前端定位引用；未解析文档触发索引时会记录 `index_status=failed` 和 `index_error`。默认 `VECTOR_DB_BACKEND=local-json`、embedding adapter 为 deterministic `local-hash`，便于离线测试；未接入的后端（例如 `faiss`/`chroma`）不会静默降级到本地 JSON，索引会失败并记录 `unsupported vector db backend`。后续可替换为 Chroma/FAISS/外部 embedding。Streamlit 文档页展示章节预览、`parse_error`、翻译预览、索引状态和 chunk/vector 定位。`POST /rag/query` 请求体与响应：

```json
// 请求
{ "question": "Ar/O2 ICP 里 O- 的主要生成通道是什么？",
  "document_ids": [42], "top_k": 6 }

// 响应（答案必须带引用溯源，便于研发核对）
{
  "answer": "主要通过电子离解吸附 e + O2 -> O- + O ...\n\nSource: paper_id=42; title=Example plasma paper; section=3.2 Reaction kinetics; chunk_id=511",
  "sources": [
    { "document_id": 42, "paper_id": 42, "paper_title": "Example plasma paper",
      "section_title": "3.2 Reaction kinetics",
      "chunk_id": 511, "vector_id": "doc-42-section-9-chunk-1",
      "score": 0.82, "source_excerpt": "In the Ar/O2 plasma, O- is mainly produced by ..." }
  ]
}
```

## 模块 H — 化学库抽取（交付物）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/documents/{id}/extract-chemistry` | 触发结构化抽取 |
| GET | `/documents/{id}/reaction-sets` | 该文档的反应集列表 |
| GET | `/reaction-sets/{id}` | 反应集详情（含所有反应） |
| PUT | `/reactions/{id}/verify` | 单条反应人工复核 |
| POST | `/reaction-sets/{id}/export` | 导出仿真输入格式 |

`POST /documents/{id}/extract-chemistry` 响应 `202`：

```json
{
  "job_id": 42,
  "document_id": 42,
  "chemistry_status": "extracting",
  "status": "pending"
}
```

抽取响应（初始 `status=pending`，等待人工复核）：

```json
{
  "id": 17, "document_id": 42, "gas_mixture": "Ar/O2",
  "lxcat_db": "IST-Lisbon", "status": "pending",
  "reactions": [
    { "id": 201, "reaction": "e + Ar -> e + e + Ar+",
      "reaction_type": "ionization", "rate_type": "cross_section",
      "threshold_ev": 15.76, "cross_section_url": "https://lxcat.net/...",
      "source_section_id": 88, "source_section_title": "3.2 Reaction kinetics",
      "source_section_type": "table", "source_section_seq": 7,
      "source_label": "table 7: 3.2 Reaction kinetics",
      "source_excerpt": "原文命中片段...",
      "confidence": 0.91, "verified": 0, "audit_log": [] }
  ]
}
```

`PUT /reactions/{id}/verify` 请求体：`{ "verified": true, "reaction_type": "ionization", "rate_type": "cross_section", "rate_value": "...", "threshold_ev": 15.76, "cross_section_url": "https://...", "verified_by": "engineer_a" }`。复核允许顺手修正字段，并写入 `reaction_audits`；显式传入 `reaction_type: null`、`rate_type: null`、`rate_value: null`、`threshold_ev: null` 或 `cross_section_url: null` 会清空对应字段，并在审计日志中保留该清空动作；未传字段则保持原值。`GET /reaction-sets/{id}` 会在每条 reaction 下返回 `audit_log`。抽取任务会更新 `documents.chemistry_status`：`extracting/extracted/rejected/failed`，失败或无反应时写 `chemistry_error`。抽取结果必须保留 `source_section_id`、`source_section_title`、`source_section_type`、`source_section_seq`、`source_label` 和 `source_excerpt`，用于人工核对和导出追溯。系统会从原文中保守识别 `LXCat <db>` 和包含 `lxcat` 的 URL，分别填入 `reaction_sets.lxcat_db` 与 `reactions.cross_section_url`；不联网抓取或臆造截面数据。**只有当反应集内所有反应 `verified=1` 时，`export` 才放行** —— 这是速率系数的人工闸门，不可绕过。`export?format=json` 输出结构化 JSON，`format=txt` 输出简表文本并保留 `confidence/source_label/source_section_title/source_section_type/source_section_seq/source_excerpt`，`format=bolsig` 输出 BOLSIG+/LXCat 兼容反应摘要文本并带 `confidence`、`source_label` 与完整 source section 信息；三种格式分别写入 `.json`、`.txt`、`.bolsig.txt` 文件，避免互相覆盖。导出响应包含 `reaction_set_id`、`format`、`output_path`、`mime_type`、`reaction_count`、`audit_entry_count`，便于前端和发布 smoke 直接确认交付物规模与复核审计记录数量。未知格式返回 400 `unsupported_export_format`。

`GET /documents/{id}/reaction-sets` 支持 `page`、`page_size`，响应遵循统一列表结构。

## 建议落地顺序

每个阶段都有可独立演示的产出，建议按周推进。

**阶段 1 · 确定性检索层（先跑通这一层就是完整系统）**
表：`journals`、`papers`、`crawl_jobs`、`categories`、`paper_categories`。
接口：模块 A、B、C、D。
可演示：白名单抓取 → 检索界面按关键词/分类/日期出文章列表，带 OA 链接可跳转。

**阶段 2 · 导入与解析**
表：`documents`、`sections`、`translations`。
接口：模块 E、F。
可演示：导入 PDF → GROBID 解析出章节 → 中英对照翻译（公式不乱）。

**阶段 3 · RAG**
表：`chunks` + 外部向量库。
接口：模块 G。
可演示：对导入文献提问，回答带原文引用溯源。

**阶段 4 · 化学库抽取**
表：`reaction_sets`、`reactions`。
接口：模块 H。
可演示：从文献抽出反应集 + 对接 LXCat → 工程师复核 → 导出仿真输入。
