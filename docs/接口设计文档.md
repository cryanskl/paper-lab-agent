# 等离子体文献系统 · 接口设计文档

配套数据库见 `schema.sql`（SQLite，`sqlite3 plasma.db < schema.sql` 即可建库并写入 6 本白名单期刊）。

## 总览

系统分两层，异步解耦：

- **确定性检索层**：按白名单 ISSN 限定期刊来源；用户在线搜索时把 OR/AND 搜索词和日期范围下推给 OpenAlex/Crossref，命中元数据写入本地缓存，并用 Unpaywall 补全合法 OA 链接。
- **大模型理解层**：用户检索→人工下载 PDF→导入后，才触发 GROBID 解析、翻译、RAG、化学库抽取。

建议技术栈：FastAPI + SQLite + APScheduler（调度）+ GROBID（解析）+ Chroma/FAISS（向量库）。唯一前端为 FastAPI 托管的原生 HTML/CSS/JS 工作台。

## 通用约定

- 基址：`/api/v1`，请求与响应均为 `application/json`（文件上传除外）。
- 列表统一分页：query 参数 `page`（默认 1）、`page_size`（默认 20）；响应统一为
  `{ "items": [...], "total": <int>, "page": <int>, "page_size": <int> }`。
- 错误统一为 `{ "error": { "code": "...", "message": "..." } }`，配合语义化 HTTP 状态码（400/404/409/422/500）。
- 耗时操作（抓取、解析、翻译、索引、抽取）一律异步：立即返回
  `{ "job_id": <id>, "status": "pending" }`，前端轮询对应资源的状态字段。
- 起步阶段不做鉴权；上线前再在网关或中间件统一加。

## 模块 0 — 系统状态

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 轻量存活探针，返回服务名与 `ok` 状态 |
| GET | `/system/status` | 本地存储、外部能力配置和资源计数 |

响应的 `counts` 至少包含：`journals`、`papers`、`downloaded_papers`、`categories`、`paper_categories`、`crawl_jobs`、`search_history`、`search_results`、`documents`、`sections`、`translations`、`chunks`、`prompt_presets`、`reaction_sets`、`reactions`、`reaction_audits`，用于发布验收和本地排障确认核心资源是否已初始化/产出；`downloaded_papers` 只统计 `paper_downloads.status=downloaded` 的成功下载论文，不包含手工上传文档；`search_history/search_results` 用于确认联网搜索缓存批次及其结果关联已经落库。

响应的 `status_counts` 按既有状态字段汇总工作流分布，至少包含：`crawl_jobs`、`search_history`、`document_parse`、`document_index`、`document_chemistry`、`translations`、`reaction_sets`。每个子对象形如 `{ "failed": 2, "success": 5 }`，用于发布后快速判断搜索、解析、索引、翻译、化学抽取或反应集复核是否有失败或积压。

响应的 `demo_data` 用于确认本地 walking skeleton 是否已经准备好，结构为 `{ "ready": true, "requirements": {"papers": 1}, "missing": [], "counts": {"papers": 2} }`。`ready=false` 时 `missing` 返回缺失门槛列表，例如 `["documents>=1", "chunks>=1"]`，与 `python scripts/health_check.py --require-demo-data` 的发布前门禁一致。

响应的 `release_readiness` 汇总发布前核心门禁，结构为 `{ "ready": false, "demo_data_missing": [], "failed_workflows": [], "config_warning_codes": [], "storage_errors": [] }`。`ready=true` 表示本地存储可写、无失败、拒绝或未知状态的工作流，且 walking skeleton 演示数据已满足门槛；`config_warning_codes` 仍会返回配置提示。缺少 `OPENALEX_API_KEY`、`UNPAYWALL_EMAIL` 或 `LLM_API_KEY` 等可选外部能力不阻断基础发布就绪判断；但 `unsupported_embedding_model` 或 `unsupported_vector_db_backend` 表示 RAG adapter 不受当前 registry 支持，会导致 `release_readiness.ready=false`。`failed_workflows` 会把 `failed`、需要人工处理的 `rejected` 和无法判定的 `unknown` 状态都列为阻断项，例如 `document_chemistry.rejected=1` 或 `document_parse.unknown=1`；状态字段为 `NULL` 或空白字符串时统一按 `unknown` 统计。向量库存在但无法读取或解析时，`storage_errors` 会包含 `vector_db.valid_json`，避免 RAG 索引损坏被误判为可发布；该字段名为兼容既有接口保留，Chroma 后端下表示持久化 collection 可正常打开，而非字面意义上的 JSON 文件。

响应的 `runtime` 至少包含：`api_prefix`、`scheduler_enabled`、`scheduler_jobs`、`version`，用于确认当前 API 路径、调度器开关、已注册的 daily/weekly/monthly 抓取计划和部署版本。`scheduler_jobs` 每项包含 `id`、`period`、`trigger`、`schedule`、`timezone`，便于发布后核对 APScheduler 实际周期。

响应的 `storage_health` 至少包含：`data_dir`、`pdf_dir`、`tei_dir`、`translation_dir`、`export_dir`、`database`、`database_parent`、`vector_db_parent`。目录项和 `database` 文件项结构为 `{ "path": "...", "exists": true, "writable": true }`，用于排查新机器目录不存在、SQLite 文件缺失或不可写的问题。`vector_db` 为文件级健康项，结构为 `{ "path": "...", "exists": true, "readable": true, "writable": true, "valid_json": true, "error": null }`；当本地向量索引 JSON 损坏时 `valid_json=false` 且 `error` 给出解析错误，便于在触发 RAG 前排障。

响应的 `config_warnings` 为非阻断配置提示数组，每项结构为 `{ "code": "...", "capability": "...", "message": "..." }`。缺少 `OPENALEX_API_KEY`、`UNPAYWALL_EMAIL` 或 `LLM_API_KEY` 时只返回 warning，不阻止 API 启动、fixture 导入或基础检查。

`GET /system/status?check_external=true` 会主动检查 GROBID `/api/isalive`，响应的 `external_capabilities.grobid` 包含 `url`、`available`、`status_code`、`error`。`external_capabilities.openalex_api_key`、`openalex_mailto`、`unpaywall_email` 和 `llm_api_key` 只暴露是否已配置，不返回凭据内容。`external_capabilities.translation_adapter` 暴露当前翻译 adapter：未配置 `LLM_API_KEY` 时为 `unavailable`，已配置时为 `openai-compatible`；`external_capabilities.llm_model` 暴露当前配置的翻译模型名但不暴露 key。`external_capabilities.vector_db_backend` 暴露当前向量库后端，默认 `chroma`；未支持的 backend 会出现在 `config_warnings` 中，并且 RAG 索引/查询会明确失败。不传 `check_external` 时不主动访问外部服务。

## 模块 A — 期刊白名单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/journals` | 列出白名单，支持 `?active=1` |
| POST | `/journals` | 新增期刊 |
| GET | `/journals/{id}` | 详情 |
| PUT | `/journals/{id}` | 更新来源信息 / 年限 / 启停 |
| DELETE | `/journals/{id}` | 软删（置 `active=0`） |

`POST /journals` 请求体：

```json
{
  "name": "Plasma Sources Science and Technology",
  "publisher": "IOP Publishing",
  "issn_print": "0963-0252",
  "issn_electronic": "1361-6595",
  "keywords": [],
  "year_from": 1990
}
```

`keywords` 仅为旧数据库/API 客户端兼容字段，可省略或传空数组；在线搜索不再使用期刊级关键词作为论文准入门槛。新增搜索词统一通过 `POST /crawl/run` 的 `search_terms` 与 `search_mode` 提交。

`issn_print` 与 `issn_electronic` 会自动去除首尾空白，并将校验位 `x` 归一为 `X`；非空值必须符合 `####-###X` 格式，最后一位可为数字或 `X`。

## 模块 B — 抓取调度

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/crawl/run` | 手动触发一次抓取（定时任务调用同一逻辑） |
| POST | `/crawl/searches/{id}/save` | 将搜索批次中的新增预览论文保存到正式本地库 |
| DELETE | `/crawl/searches/{id}` | 撤销搜索批次并安全清理无下游引用的预览论文 |
| GET | `/crawl/jobs` | 抓取任务列表 |
| GET | `/crawl/jobs/{id}` | 单次任务状态与统计 |

`POST /crawl/run` 请求体（字段均可选；不传 `journal_ids` 则跑全部 active 期刊）：

```json
{
  "journal_ids": [2, 5],
  "period": "manual",
  "date_from": "2026-06-01",
  "date_to": "2026-06-23",
  "search_terms": ["plasma chemistry", "surface reaction"],
  "search_mode": "or",
  "max_results": 50,
  "force_refresh": false
}
```

`search_terms` 为 1–20 个词或短语；`search_mode` 为 `or`（默认，任一词/短语命中）或 `and`（全部命中）。系统把布尔表达式下推给元数据源做相关度召回，再在标题、摘要、DOI 与作者字段上按同一规则复核。`max_results` 范围 1–100，工作台提供 20/50/100 三档并默认 50；它是所有期刊合计的全局上限，每本期刊的候选召回可保留少量过滤余量，但最终写入 `search_results` 的数量不得超过该上限。

旧客户端仍可提交 `search_query`；兼容语义为按空白拆分后 AND。新客户端不得同时依赖 `search_query` 与 `search_terms`，存在 `search_terms` 时以后者为准。

手动搜索会以“规范化搜索词 + OR/AND + 期刊范围 + 每本期刊日期范围 + max_results”生成缓存键并写入 `search_history`。24 小时内精确重复、上次全部成功且批次未被撤销时直接返回 `cache_hit=true`，不重复访问学术 API；`force_refresh=true` 可绕过缓存。论文元数据仍只存于 `papers`；`search_results` 保存批次与论文的关联、是否为本次新增以及最小审计快照。

手动联网搜索新增论文写入 `papers` 时使用 `library_status=preview`，默认 `GET /papers` 不返回这些预览论文；传入 `search_id` 时只返回该批次结果，可同时看到既有馆藏命中和新增预览。用户通过 `POST /crawl/searches/{id}/save` 确认后，批次新增论文改为 `saved` 并进入正式本地库。`DELETE /crawl/searches/{id}` 撤销该批次：仅删除由该批次首次新增、没有其他有效批次依赖且没有关联全文文档的论文；已有 PDF 及其翻译、索引、化学数据，或被其他已保存批次引用的论文保留，并在响应中计入 `preserved_count`。

响应 `202`：

```json
{
  "jobs": [
    {
      "job_id": 42,
      "journal_id": 2,
      "period": "weekly",
      "date_from": "2026-06-01",
      "date_to": "2026-06-23",
      "status": "pending"
    }
  ],
  "search_id": 18,
  "decision_status": "preview",
  "cache_hit": false,
  "cache_ttl_hours": 24,
  "result_count": 0
}
```

搜索逻辑：按期刊 ISSN、日期与布尔搜索表达式调用 OpenAlex/Crossref → 按相关度获取有限候选 → 字段归一化（OpenAlex `abstract_inverted_index` 会还原为普通摘要文本，Crossref JATS/HTML 摘要会清理为纯文本）→ 在标题、摘要、DOI、作者上复核 `search_terms/search_mode`，并过滤 `paratext` 等明确的非研究记录 → 等所有期刊候选到齐后，保留每刊内部相关度顺序并在期刊间轮询选择，空期刊自动让出名额，按 DOI/保守指纹跨刊去重并执行 `max_results` 全局封顶 → 对入选且缺摘要的 OpenAlex DOI 尝试用 Crossref 公开元数据补全 → 写入 `papers` 和 `search_results`（DOI 去重，命中即更新；无 DOI 时用 `dedupe_key` 做保守去重；空的上游摘要/作者不覆盖已有非空字段；新增论文先为预览状态）→ 逐条调 Unpaywall 补 `oa_pdf_url` → 触发分类。期刊表中的旧 `keywords` 不参与过滤。全程记录到 `crawl_jobs`、`search_history` 与 `search_results`；OpenAlex 返回空列表或临时异常时会尝试 Crossref fallback。

多个期刊任务会以有限并发方式执行，默认同时处理 3 本期刊，可通过 `.env` 的 `CRAWL_MAX_CONCURRENCY` 在 1–10 之间调整。每本期刊仍保留独立 `crawl_jobs` 记录；网络请求在 SQLite 写事务之外并发执行，单本期刊的入库与统计仍在同一事务内完成。

OpenAlex/Crossref 请求受 `.env` 中 `ACADEMIC_API_MAX_PAGES`、`ACADEMIC_API_MAX_RETRIES`、`ACADEMIC_API_RETRY_BACKOFF_SECONDS`、`ACADEMIC_API_TIMEOUT_SECONDS` 控制；Unpaywall 请求受 `UNPAYWALL_API_MAX_RETRIES`、`UNPAYWALL_API_RETRY_BACKOFF_SECONDS`、`UNPAYWALL_API_TIMEOUT_SECONDS` 控制。遇到 429 时优先尊重 `Retry-After`，否则按 backoff 退避。OpenAlex 请求使用 `OPENALEX_API_KEY`；`OPENALEX_MAILTO` 作为联系邮箱写入 OpenAlex/Crossref User-Agent，并继续传给 Crossref 的 `mailto` 参数。

`crawl_jobs` 统计字段：`papers_found` 为元数据 API 返回的有限候选量，`papers_filtered` 为本地复核或数量封顶剔除量，`papers_new` 为新增入库量；`search_terms`、`search_mode`、`max_results` 和 `search_history_id` 用于解释本次搜索条件。

`GET /crawl/jobs` 的每个 `items[]` 与 `GET /crawl/jobs/{id}` 除返回 `crawl_jobs` 行字段外，还返回：

- `journal`：当前任务对应期刊摘要，包含 `id`、`name`、`issn_print`、`issn_electronic`、`active`。
- `diagnostics`：除通用统计外返回 `search_mode`、`search_terms`、`max_results`；兼容字段 `keyword_mode="disabled"`、`keyword_terms=[]` 明确表示期刊级关键词门槛已停用。

## 模块 C — 文献检索（核心）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/papers` | 检索（见下方参数） |
| GET | `/papers/{id}` | 文献详情 |
| GET | `/paper-downloads` | 下载任务管理列表 |
| POST | `/papers/{id}/download` | 后台下载合法 OA PDF 到本地文献库 |
| POST | `/papers/{id}/resolve-oa` | 用 Unpaywall 重新解析 OA 链接 |
| POST | `/papers/{id}/classify` | 触发 LLM 分类 |
| PUT | `/papers/{id}/categories` | 人工覆盖分类 |

`GET /papers` query 参数：`q`（全文检索标题、摘要、作者与 DOI，走 FTS5）、`q_mode`（可选 `or/and`；提供时把 `q` 按中英文逗号、分号或换行拆成词/短语并按布尔关系组合）、`result_limit`（可选 1–100，全局封顶结果数）、`search_id`（可选；只返回指定联网搜索批次，包含该批次的预览论文）、`category`（slug）、`journal_id`、`year_from`、`year_to`、`oa_only`、`downloadable_only`、`downloaded_only`、`sort`（`date_desc` / `relevance`；API 未指定时仍为 `date_desc`，Web 搜索工作台默认显式传 `relevance`）、`page`、`page_size`。`downloadable_only=true` 表示 OA PDF URL 可以进入下载流程；`downloaded_only=true` 表示 PDF 已成功保存并关联本地文献库。未传 `search_id` 时只返回 `library_status=saved` 的正式本地库论文。

`POST /papers/{id}/download` 返回 `202`：`{job_id,paper_id,document_id,status,error}`。后端只读取该论文已经入库的 `oa_pdf_url`，不接受调用方传入任意 URL；请求及每次重定向均拒绝本机、私网、保留地址、带凭据 URL 和测试域名，最多跟随 3 次重定向。响应必须是 PDF、文件签名包含 `%PDF-`，且大小不得超过 100 MiB。下载请求只可转发当前浏览器的 `User-Agent`，不得转发 `Cookie`、`Authorization` 或其他用户会话信息；来源若需要登录、验证码或其他访问控制，任务记为 `failed`，不尝试绕过。

任务状态保存在 `paper_downloads`。前端通过 `GET /papers/{id}` 或重新检索轮询 paper 对象的 `download` 字段：`{status,error,document_id,downloaded_at}`。可下载但尚未开始时为 `available`，后台执行时为 `downloading`，本地文献已创建时为 `downloaded`，最近一次失败时为 `failed`，没有合法 OA PDF URL 时为 `unavailable`。重复触发已下载论文是幂等操作，直接返回现有 `document_id`；失败任务可以重新触发。

`GET /paper-downloads` 支持 `status`（`pending/downloading/downloaded/failed`）、`page`、`page_size`，返回 `{items,total,page,page_size,status_counts}`。每个 item 包含任务字段及 `paper:{id,doi,title,journal_name,published_date}`；下载管理页用它展示进度、失败原因、重试入口及已下载文档的 `document_id`。

响应示例：

```json
{
  "items": [
    {
      "id": 1287,
      "doi": "10.1088/1361-6595/abxxxx",
      "title": "Global model of an Ar/O2 inductively coupled plasma",
      "journal_name": "Plasma Sources Science and Technology",
      "published_date": "2026-05-12",
      "oa_status": "green",
      "oa_pdf_url": "https://repository.example/...pdf",
      "landing_url": "https://iopscience.iop.org/article/...",
      "source_api": "openalex",
      "dedupe_key": "doi:10.1088/1361-6595/abxxxx",
      "has_doi": true,
      "dedupe_strategy": "doi",
      "categories": ["sources", "chemistry", "methods"],
      "category_details": [
        {
          "id": 1,
          "slug": "sources",
          "name": "放电与等离子体源",
          "confidence": 0.86,
          "method": "auto"
        },
        {
          "id": 2,
          "slug": "chemistry",
          "name": "等离子体化学",
          "confidence": 1.0,
          "method": "manual"
        }
      ]
    }
  ],
  "total": 43, "page": 1, "page_size": 20
}
```

`source_api`、`dedupe_key`、`has_doi`、`dedupe_strategy` 用于审计保守去重：有 DOI 时 `dedupe_strategy=doi`；无 DOI 文献会用 `no-doi:<sha256>` 形式的 `dedupe_key` 并返回 `dedupe_strategy=no_doi_fingerprint`，避免同一来源页/标题/日期重复入库，同时让前端和排障工具能解释合并原因。

`categories` 保留为向后兼容的 slug 列表；`category_details` 返回同一批分类的完整结构，包含分类 `id`、`slug`、`name`、`confidence` 和 `method`（`auto` 或 `manual`），用于前端展示置信度和人工覆盖状态。

`PUT /papers/{id}/categories` 请求体：`{ "category_ids": [1, 2, 6], "method": "manual" }`。

检索结果自带的摘要可独立翻译，不要求先上传 PDF：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/papers/{id}/abstract-translation` | 异步翻译论文元数据中的摘要，body `{ "target_lang": "zh" }` |
| GET | `/papers/{id}/abstract-translation?target_lang=zh` | 获取该目标语言最新的摘要译文与状态 |

`POST` 返回 `202`，结构为 `{job_id,paper_id,target_lang,status}`。系统按
`paper_id + target_lang + source_text` 复用已完成译文；论文摘要发生变化时创建新任务，不复用旧摘要的译文。
`GET` 返回 `{id,paper_id,source_lang,target_lang,source_text,target_text,status,error,created_at,updated_at}`。
论文不存在返回 `404 paper_not_found`；元数据没有非空摘要时返回
`409 paper_abstract_missing`。摘要翻译写入 `paper_abstract_translations`，与依赖 PDF/GROBID
章节的全文翻译相互独立。

## 模块 D — 分类体系

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/categories` | 列出分类（含层级） |
| POST | `/categories` | 新增分类 |
| PUT | `/categories/{id}` | 编辑分类名称、slug 与说明；保留文献关联 |
| DELETE | `/categories/{id}` | 删除分类及其文献关联；存在直接子分类时拒绝 |

`GET /categories` 遵循统一列表结构：`{items,total,page,page_size}`。`items` 保留扁平分类列表，每个分类带 `children` 数组表示直接子分类，并带 `paper_count` 表示当前关联文献数，便于前端同时支持树形展示、扁平选择和删除前影响提示。

`POST /categories` 会对 `slug` 做首尾空格清理、小写规范化，并将内部空白归一为 `-`；归一后的 slug 只能包含小写字母、数字、连字符或下划线，保证 taxonomy slug 可稳定用于筛选、分类落库和前端默认选中。

`PUT /categories/{id}` 请求体为 `{name,slug,description}`，使用与新增分类相同的名称、slug 规范化与唯一性约束。更新只修改 `categories` 行，不替换分类 id，因此既有 `paper_categories` 文献关联与子分类关系保持不变；分类不存在返回 `404 category_not_found`，名称或 slug 冲突返回 `409 category_conflict`。

`DELETE /categories/{id}` 返回 `{id,name,slug,removed_paper_links}`。删除分类时依赖 `paper_categories.category_id ON DELETE CASCADE` 同一事务清理文献关联；若分类不存在返回 `404 category_not_found`，仍有直接子分类时返回 `409 category_has_children`，需先处理子分类，避免隐式删除整棵 taxonomy。

## 模块 E — 文档导入与解析

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/documents` | 上传 PDF（multipart：`file`，可选 `paper_id`、`auto_process`、`target_lang`） |
| GET | `/documents` | 已导入文档列表 |
| GET | `/documents/{id}` | 详情（含 `parse_status`） |
| GET | `/documents/{id}/file` | 在浏览器内打开已保存的本地 PDF |
| GET | `/documents/{id}/figures` | 列出 TEI 中可定位的论文图片 |
| GET | `/documents/{id}/figures/{figure_id}/image` | 按 GROBID 坐标裁剪论文图片 |
| POST | `/documents/{id}/parse` | 触发 GROBID 解析 |
| GET | `/documents/{id}/sections` | 解析出的结构化章节 |

`GET /documents` 与 `GET /documents/{id}/sections` 均支持 `page`、`page_size`，响应遵循统一列表结构。

`POST /documents`、`GET /documents`、`GET /documents/{id}` 返回的 document 对象除 `documents` 行字段外，还包含 `paper`：若 `paper_id` 已关联论文，`paper` 为 `{id,doi,title,journal_name,published_date}`；未关联时为 `null`。重复上传返回的 `409 document_duplicate` payload 中 `document` 也遵循同一结构。

上传 PDF 默认不得超过 100 MiB，可通过 `.env` 的 `MAX_PDF_UPLOAD_BYTES` 调整（1–1073741824 bytes）。服务端只读取“上限 + 1”字节用于判定，超限返回 `413 + {error:{code:"document_too_large",message}}`，且不会写入 PDF 文件或 document 记录。

`GET /documents/{id}/file` 是文件响应例外：只允许读取该 document 的 `file_path`，且路径必须是 `PAPER_LAB_PDF_DIR` 下无符号链接的普通 PDF 文件；成功返回 `application/pdf` 与 `Content-Disposition: inline`。文件缺失、越过受控目录、不是普通文件或不是 PDF 时返回统一 JSON 错误，不接受调用方提供文件路径。

`GET /documents/{id}/figures` 从该文档受控 `tei_path` 的 `<figure><graphic coords="page,x,y,width,height">` 读取图片定位信息，返回 `{items,total,page,page_size}`；每项为 `{id,label,title,caption,page,x,y,width,height,image_url}`。`GET /documents/{id}/figures/{figure_id}/image` 是图片文件响应例外：后端只接受列表中实际存在的安全 figure id，并使用对应坐标从该 document 的受控 PDF 裁剪 PNG，不接受调用方提供坐标或文件路径。无坐标、越界页码、非法矩形、缺失 PDF/TEI 或符号链接路径均返回统一 JSON 错误。

`POST /documents` 的 `auto_process` 默认为 `false`。设为 `true` 时，上传成功后立即把文档标记为 `parsing` 并在后台执行完整处理流水线：解析成功后依次触发 `target_lang`（默认 `zh`）翻译、RAG 索引和化学库抽取。解析失败时停止后续步骤；解析成功后，任一派生步骤失败不阻塞其余步骤，并分别写入现有 translation/index/chemistry 状态。接口仍以 `201` 立即返回 document，不等待流水线完成；重复文档的 `409` 不自动重跑流水线。

`POST /documents/{id}/parse` 响应 `202`：

```json
{
  "job_id": 42,
  "document_id": 42,
  "parse_status": "parsing",
  "status": "pending"
}
```

上传时按 `file_hash` 去重；命中已有则直接返回旧记录（409 + 已有资源）。解析完成后 `parse_status=parsed`，章节写入 `sections`，TEI 落盘到 `tei_path`。重新解析同一文档时会清理旧 `chunks`、向量索引、翻译和化学抽取结果，并将 `index_status` 置回 `not_indexed`、`chemistry_status` 置回 `not_extracted`，避免旧 section 派生产物继续被使用。TEI 解析覆盖 `abstract`、正文 `body`、`table`、`figure_caption`、`reference`。GROBID 不可用或返回异常但本地文本 fallback 成功时，`parse_status` 仍为 `parsed`，`parse_error` 记录降级原因；完全失败时 `parse_status=failed` 且 `parse_error` 记录失败原因。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/documents/{id}/translate` | 触发翻译，body `{ "target_lang": "zh" }` |
| GET | `/documents/{id}/translation` | 取翻译结果/状态 |
| POST | `/term-translations` | 创建阅读页术语翻译任务 |

| POST | `/glossary-terms` | 新增术语 |
| PUT | `/glossary-terms/{id}` | 编辑术语 |
| DELETE | `/glossary-terms/{id}` | 删除术语 |
| POST | `/glossary-terms/import` | 一次性合并旧浏览器术语 |

`POST /documents/{id}/translate` 响应 `202`：

```json
{
  "job_id": 17,
  "document_id": 42,
  "target_lang": "zh",
  "status": "pending"
}
```

`POST /term-translations` 请求体为
`{source_text,source_lang,target_lang,context_text?}`，其中术语最长 120 字符，
上下文最长 1000 字符；响应 `202`：

```json
{
  "job_id": 23,
  "source_text": "deterministic fixture",
  "source_lang": "en",
  "target_lang": "zh",
  "status": "pending"
}
```

任务由 BackgroundTasks 调用已配置的 OpenAI-compatible 模型。完成后
`GET /term-translations/{id}` 返回
`{id,source_text,source_lang,target_lang,context_text,target_text,status,error,created_at,updated_at}`。
相同术语、语言方向和上下文已有 `done` 结果时可直接复用缓存。未配置
`LLM_API_KEY` 或模型调用失败时任务为 `failed`，不得用原文冒充译文。

术语表使用 `glossary_terms` 表持久化到 `DATABASE_PATH` 指向的本地 SQLite，
不以浏览器 `localStorage` 作为数据源。`GET /glossary-terms` 返回统一分页结构；
新增与编辑请求为
`{en?,zh?,translation_job_id?,translation_status?,translation_error?}`，中英文至少一项非空，
单项最长 120 字符；有英文时按英文、仅有中文时按中文做大小写不敏感去重，以允许多个英文缩写共享中文释义。`POST /glossary-terms/import`
请求为 `{items:[...]}`，逐项合并旧浏览器数据并返回完整分页结构；重复项不重复写入。
删除返回 `{id,en,zh}`。资源不存在返回 404，重名冲突返回 409。

`target_lang` 会自动去除首尾空白；非空值不得包含路径分隔符或控制字符，避免翻译记录和本地产物路径出现不稳定标识。

`GET /documents/{id}/translation` 除返回 `translations` 行字段外，还返回 `sections`：把 `output_path` 指向的双语 markdown 按 `## ` 切回块，并与 `sections` 表按 `seq` 顺序对齐，供前端双语阅读页做段落级对照。每项结构为 `{section_id, seq, title, section_type, source, target, note}`；`note` 保留 `table`/`reference` 等免翻译章节的说明行，不混进 `target`。翻译尚未完成、`output_path` 缺失、指向符号链接或文件不可读时 `sections` 为 `[]`，不抛错，便于前端按 `status` 区分「未翻译 / 翻译中 / 翻译失败」。

实现要点：翻译前先把公式区域（行内 `$...$` 与行间公式）替换成不可翻译占位符（如 `<EQ_007>`），再按 `TRANSLATION_CHUNK_CHARS`（默认 6000 字符）把超长章节优先沿段落或句子边界分块，只送已保护的纯文字给模型，全部译完后校验并回填公式。OpenAI-compatible 请求的读取超时由 `LLM_REQUEST_TIMEOUT_SECONDS` 控制（默认 180 秒）。配置 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL` 后使用 OpenAI-compatible `/chat/completions` adapter；未配置 `LLM_API_KEY` 时文档、摘要和术语翻译端点返回 `409 + {error:{code:"translation_unavailable",message}}`，且不创建翻译任务。翻译任务创建后写入相应翻译表，成功为 `status=done + output_path/target_text`，模型调用失败为 `status=failed + error`，例如未解析文档会记录 `document has no parsed sections`。

## 模块 G — RAG 知识库

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/documents/{id}/index` | 分块 + 向量化入库 |
| GET | `/documents/{id}/chunks` | 查看索引状态与 chunk/vector 映射 |
| POST | `/rag/query` | 提问检索 |

`POST /documents/{id}/index` 响应 `202`：

```json
{
  "job_id": 42,
  "document_id": 42,
  "index_status": "indexing",
  "status": "pending"
}
```

分块保留 `sections` 章节边界，章节内优先在自然段和中英文句末切分；长度由当前 embedding adapter 的 tokenizer 计算，默认目标 `RAG_CHUNK_TARGET_TOKENS=450`、允许为保留完整句子延长到 `RAG_CHUNK_MAX_TOKENS=600`，相邻块保留 `RAG_CHUNK_OVERLAP_TOKENS=60` 的上下文。超长句子才按 token 边界硬切，chunk 不跨 section。每个 chunk 写入 `chunks`，并同步写入 `VECTOR_DB_PATH` 指向的向量库。产品与发布默认使用 `EMBEDDING_MODEL=bge-m3` + `VECTOR_DB_BACKEND=chroma`，此时 `VECTOR_DB_PATH` 是 Chroma 持久化目录；旧的 `local-hash/local-json` 只用于历史索引迁移诊断兼容。`local-json` 的读改写由跨进程文件锁保护，并通过同目录临时文件原子替换，避免并发写丢失或留下半截 JSON。向量记录保留 `chunk_id`/`section_id` 回链，并记录 `embedding_model` 与 `vector_db_backend`；查询必须使用当前配置的同一索引契约。所选文档中只要存在模型或后端元数据不匹配的旧向量，`POST /rag/query` 就返回 `409 + {error:{code:"rag_index_contract_mismatch",message}}` 并提示重建索引，不会退回 SQLite 词法结果掩盖错配。切换模型、后端或切分参数后必须重新建立文档索引。重建同一文档索引时会先替换该文档旧向量，避免 RAG 命中已删除 chunk。`GET /documents/{id}/chunks` 支持 `page`、`page_size`，返回 `{items,total,page,page_size,indexed,index_status,index_error}`，每个 item 含 `section_title` 与 `vector_id`，供前端定位引用；未解析文档触发索引时会记录 `index_status=failed` 和 `index_error`。未接入的后端（例如 `faiss`）不会静默降级，索引会失败并记录 `unsupported vector db backend`。原生工作台文档页展示章节预览、`parse_error`、翻译预览、索引状态和 chunk/vector 定位。

当 `POST /rag/query` 显式传入 `document_ids` 并设置 `use_document_context=true` 时，问答会把对应文档已经解析出的 `sections` 直接作为模型上下文，**不要求预先建立 RAG 索引**。若已存在索引，索引仍可用于增强长文检索和定位；`use_document_context=false`（默认）的知识库问答继续按已索引 `chunks` 检索。直接文档问答的 `sources` 以 `section_id` / `section_seq` 回链原文，此时 `chunk_id` / `vector_id` 可以为 `null`。模型使用内部 source id 生成机器可读来源尾注，服务端在响应前解析并移除尾注，因此 `answer` 只包含可安全渲染的 Markdown 正文，不暴露 `[S1]` 等内部标记。无论是否使用索引，模型都只能依据返回的当前文献来源回答；证据不足时必须明确说明，不得猜测。

`POST /rag/query` 请求体与响应：

```json
{
  "answer": "### 主要通道\n\n主要通过电子离解吸附 `e + O2 -> O- + O`。",
```


`PUT /reactions/{id}/verify` 请求体：`{ "verified": true, "decision": "accepted", "reaction": "e + Ar -> e + e + Ar+", "reaction_type": "ionization", "rate_type": "cross_section", "rate_value": "...", "threshold_ev": 15.76, "cross_section_url": "https://...", "verified_by": "engineer_a" }`。`decision` 支持 `pending/accepted/rejected`；`accepted` 与 `verified=true` 对应，`pending/rejected` 与 `verified=false` 对应。省略 `decision` 时继续按旧语义把 `verified=true/false` 解释为 `accepted/pending`。`verified_by` 必填且不能为空，缺失或空白返回 422 `validation_error`，确保每次人工复核动作都有可审计责任人；内置工作台按单用户模式运行，不展示复核人输入框，统一提交 `verified_by=self` 并在界面显示为“本人”，其他 API 客户端仍须显式提供该字段。复核允许修正化学方程式与其他字段，并写入 `reaction_audits`；方程式不可清空，显式传入 `reaction_type: null`、`rate_type: null`、`rate_value: null`、`threshold_ev: null` 或 `cross_section_url: null` 会清空对应字段，并在审计日志中保留该清空动作；未传字段则保持原值。

`GET /reaction-sets/{id}` 会在顶层返回候选总数 `reaction_count`，以及 `accepted_count`、`rejected_count`、`pending_count`；兼容字段 `verified_count=accepted_count`、`unverified_count=pending_count`。当所有候选均已决定且至少一条为 accepted 时，反应集状态变为 `verified` 并进入已确认反应集；全部 rejected 时状态变为 `rejected`；仍有 pending 时保持 `pending`。`export_ready=true` 表示不存在 pending 且至少一条 accepted。每条 reaction 下返回 `review_status` 与 `audit_log`。抽取任务会更新 `documents.chemistry_status`：`extracting/extracted/rejected/failed`，失败或无反应时写 `chemistry_error`。抽取结果必须保留 `source_section_id`、`source_section_title`、`source_section_type`、`source_section_seq`、`source_label` 和 `source_excerpt`，用于人工核对和导出追溯。系统会从原文中保守识别 `LXCat <db>` 和包含 `lxcat` 的 URL，分别填入 `reaction_sets.lxcat_db` 与 `reactions.cross_section_url`；不联网抓取或臆造截面数据。**只有全部候选都完成人工决定时，`export` 才放行，且只导出 accepted 反应** —— rejected 候选保留在审计记录中但不进入仿真输入，这是速率系数的人工闸门，不可绕过。`export?format=json` 输出结构化 JSON，`format=txt` 输出简表文本并保留 `confidence/source_label/source_section_title/source_section_type/source_section_seq/source_excerpt` 以及每条 reaction 的 `audit_entries/last_verified_by/last_verified_at` 审计摘要，`format=bolsig` 输出 BOLSIG+/LXCat 兼容反应摘要文本并带 `confidence`、`source_label`、完整 source section 信息以及 `AUDIT_ENTRIES/LAST_VERIFIED_BY/LAST_VERIFIED_AT` 审计摘要；三种格式分别写入 `.json`、`.txt`、`.bolsig.txt` 文件，避免互相覆盖。导出响应包含 `reaction_set_id`、`format`、`output_path`、`mime_type`、`reaction_count`、`audit_entry_count`，便于前端和发布 smoke 直接确认交付物规模与复核审计记录数量。未知格式返回 400 `unsupported_export_format`。

`GET /documents/{id}/reaction-sets` 支持 `page`、`page_size`，响应遵循统一列表结构；每个列表项除 `reaction_sets` 行字段外，还返回 `reaction_count`、`verified_count`、`unverified_count`、`export_ready`，用于批量查看哪些反应集仍需复核以及哪些已满足导出闸门。

## 建议落地顺序

每个阶段都有可独立演示的产出，建议按周推进。

**阶段 1 · 确定性检索层（先跑通这一层就是完整系统）**
表：`journals`、`papers`、`crawl_jobs`、`categories`、`paper_categories`。
接口：模块 A、B、C、D。
可演示：白名单抓取 → 检索界面按关键词/分类/日期出文章列表，带 OA 链接可跳转。

**阶段 2 · 导入与解析**
表：`documents`、`sections`、`translations`。
接口：模块 E、F。
可演示：导入 PDF → GROBID 解析出章节 → 中英对照翻译（公式不乱）。

**阶段 3 · RAG**
表：`chunks` + 外部向量库。
接口：模块 G。
可演示：对导入文献提问，回答带原文引用溯源。

**阶段 4 · 化学库抽取**
表：`reaction_sets`、`reactions`。
接口：模块 H。
可演示：从文献抽出反应集 + 对接 LXCat → 工程师复核 → 导出仿真输入。
