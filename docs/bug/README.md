# Bug 记录约定

本目录用于记录开发或验证过程中已确认的 bug。每个已确认 bug 一个文件；不要把未复现的猜测、临时想法或产品增强写成 bug。

## 命名

使用 YYYY-MM-DD-short-slug 加 `.md` 后缀，例如：

```text
2026-06-25-rag-stale-vector.md
```

## 模板

```md
# <短标题>

## 现象

- 触发命令、接口或页面：
- 实际结果：
- 期望结果：

## 原因

- 根因：
- 影响范围：

## 修复

- 修改文件：
- 关键行为：

## 验证

- RED 证据：
- GREEN 证据：
- 完整 gate：
```

记录原则：

- 现象必须可复现或有测试失败证据。
- 必需章节不能留空；没有证据时不要创建 bug 文件。
- 原因写当前代码证据，不写推测。
- 修复和验证要引用实际命令、测试或 commit。
- 产品增强、文档补充、发布校验增强不作为 bug 记录。
