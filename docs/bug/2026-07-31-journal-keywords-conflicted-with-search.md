# 期刊主题关键词与搜索词形成双重门槛

## 现象

- 触发页面：期刊管理中配置“主题关键词”，再在文献检索栏输入另一组搜索词并执行联网搜索。
- 实际结果：旧链路先按用户搜索词召回，又按期刊主题关键词过滤；两组词没有交集时，即使论文符合本次搜索意图也可能无法入库和展示。
- 期望结果：期刊配置只决定允许搜索的来源与年份；用户搜索词是唯一内容条件，并可选择 OR / AND。

## 原因

- 抓取服务把 `journals.keywords` 当成论文准入门槛，而检索页又维护独立的 `search_query`。
- 搜索输入提示支持 DOI / 作者，但旧 FTS5 索引只有标题和摘要，页面承诺与实际检索字段不一致。
- 联网请求没有统一的结果上限和精确搜索缓存，重复搜索会再次访问外部 API。

## 修复

- 停用期刊级关键词过滤；保留旧字段仅用于数据库/API 兼容，期刊表单不再展示或提交主题关键词。
- `POST /crawl/run` 增加 `search_terms`、`search_mode`、`max_results` 与 `force_refresh`，并将布尔检索表达式下推到 OpenAlex / Crossref。
- 新增 `search_history` 精确缓存；24 小时内相同词、关系、期刊、年份和数量直接复用本地论文。
- 将本地 FTS5 扩展为标题、摘要、作者和 DOI；搜索工作台默认按相关度显示，数量默认 50，可选 20 / 50 / 100。
- 联网新增项先作为 `preview` 批次展示；用户可保存到正式本地库，或整批撤销。撤销时会保留已有全文、其他已保存批次或其他预览批次仍引用的论文。
- 跨期刊 `max_results` 在 Unpaywall 补全前原子预留，避免“最终只展示 50 篇却为每本期刊各补全 50 篇”的额外等待。

## 验证

- API 测试覆盖 OR / AND、作者与 DOI 检索、全局数量封顶、联网查询下推和 24 小时缓存命中。
- 客户端测试覆盖 OpenAlex / Crossref 的相关度请求与候选数量截断。
- Web 测试确认期刊主题关键词控件已移除，搜索关系与数量控件存在。
- 真实临时库验收：在 `Plasma Sources Science and Technology` 中以 `SiH4, dissociation`、OR、20 篇执行联网搜索，返回 20 篇；保存后精确重复搜索立即显示“本地缓存命中（24 小时内）”。
- 聚焦回归：搜索/抓取相关 `156 passed`，新增批次链路 `45 passed`，发布契约（排除工作树既有的 `starlette` 直接依赖登记项）`387 passed, 1 deselected`。
- 完整 gate：`bash scripts/release_check.sh` -> `1349 passed`，并通过 schema/API 契约、双前端启动、演示数据、健康检查、smoke 与发布制品验证。
