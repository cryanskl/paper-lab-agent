# 当前论文问答 Markdown 与引用显示紊乱

## 现象

- 当前论文问答把 `**加粗**`、`<sub>` 等格式标记直接显示为文本，回答层级和列表不易阅读。
- 引用只显示为 `[S5]` 或 `[1·¶5]`，读者无法直接判断对应段落和小节。
- 从正文选中文字发问时，问题框会附带完整“所在段落”，造成重复、冗长，并暴露内部定位提示。

## 原因

- 前端对回答统一转义后按纯文本显示，没有提供受控的 Markdown 渲染。
- 模型生成的引用标记与界面展示耦合，内部编号直接暴露给用户；模型偶尔还会在机器引用尾标后补句号。
- 选区问题同时拼接选中文字和所在段落，而当前论文正文已经由服务端作为隐式上下文传给模型。

## 修复

1. 前端新增安全 Markdown 子集渲染，支持标题、段落、列表、引用、代码、加粗和受控上下标，任意 HTML 继续转义。
2. 当前论文正文以内部 `source_id` 提供给模型；模型在回答末尾输出机器引用尾标，服务端容错解析尾部标点、清除尾标并映射为结构化来源。
3. 引用在回答下方显示为“原文第 N 段 · 小节”按钮，点击可回到左右栏对应原文。
4. 选区提问只展示选中文字和用户问题；所在段落继续作为当前论文上下文隐式提供，不再写入可见问题。

## 验证

- 定向 API 与 Web 回归：当前论文无需 RAG 索引、机器尾标清理、旧 `[Sx]` 兼容、Markdown 渲染、清晰引用和选区提示相关测试通过。
- 真实浏览器：模型返回 Markdown 小标题和列表后正常渲染；页面无 `SOURCES:`、`[Sx]` 和裸 `**`；8 个引用按钮均显示段落号与小节名，点击 `原文第 1 段 · Abstract` 后原文段落高亮定位。
- 完整 gate：`EMBEDDING_MODEL=local-hash VECTOR_DB_BACKEND=local-json .venv/bin/python -m pytest -q` → `1390 passed, 5 warnings in 227.10s`。
- `bash scripts/release_check.sh` 的前置 bug 文档校验被并发中的 `docs/bug/2026-07-31-single-document-chat-returned-raw-chunk.md` 缺少完整 gate 证据阻塞；本修复的全量测试已单独完成。
