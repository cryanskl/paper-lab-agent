# 文献库轮询产生请求风暴并吞没加载错误

## 现象

文献库存在处理中任务时，前端每 2.5 秒重新请求文档列表，并为最多 100 篇文档逐篇请求翻译、反应集和未缓存论文详情。即使用户已经离开文献库，定时器仍会继续运行；一次刷新可扇出 200 余个请求。所有请求使用 `apiOrNull()`，网络故障、服务端错误和“尚无翻译”的 404 都会变成 `null`，顶层列表失败还会把已有卡片显示为空文献库。

## 原因

旧版 `loadLibrary()` 把列表状态轮询和所有卡片详情水合绑定在同一全量流程中，没有请求复用、并发上限、差分刷新或页面生命周期控制。`apiOrNull()` 又抹掉了错误类型，使 UI 无法区分正常缺省与真实故障。

## 修复

- 同一时刻只保留一个 `libraryLoadPromise`，合并用户操作、上传回调和定时器触发的重叠刷新。
- 文档列表仍用于轻量状态轮询；翻译只在首次加载或 pending 时刷新，反应集只在首次加载或 chemistry 从 extracting 离开时刷新，论文详情继续缓存。
- 首次元数据水合限制为 6 路并发，避免大量文档同时冲击 FastAPI/SQLite。
- 轮询只在当前页面为文献库且存在处理中任务时运行，离开页面立即清除定时器。
- 只有翻译 404 被建模为“尚无翻译”；其它列表或详情错误保留已有卡片并显示可重试的页面内警告。
