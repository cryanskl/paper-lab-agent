# 多期刊在线同步被串行执行并在 3 分钟后停止页面轮询

## 现象

在 Web 工作台选择全部期刊并点击“在线同步并检索”时，接口会创建多条期刊任务，但任务表现为一本期刊完成后才开始下一本。前端等待 180 秒后显示“在线同步等待超过 3 分钟”，容易被误解为后端任务被取消。

## 原因

`POST /crawl/run` 把每本期刊分别加入同一个 FastAPI `BackgroundTasks`。Starlette 会依次执行这些 background task，因此多条任务虽然一次创建，实际仍是串行。前端另有独立的 180 秒硬编码轮询上限；该上限只停止页面等待，不会终止后端任务。

原抓取循环还会在 SQLite 写事务中等待 Unpaywall 网络请求，若直接并发会造成写锁竞争。

## 修复

- 将一次请求创建的期刊任务交给统一的并发编排器，通过信号量限制并发。
- 默认同时处理 3 本期刊，`CRAWL_MAX_CONCURRENCY` 可在 1–10 之间调整。
- 将 OpenAlex、Crossref、Unpaywall 网络等待放在 SQLite 写事务之外；每本期刊仍以单独事务原子写入论文与任务统计。
- 前端轮询保护从 3 分钟调整为 30 分钟，并明确超时不等于取消后台任务。
- 手动抓取与 APScheduler 定时抓取复用同一并发编排逻辑。

## 验证

- 有限并发测试确认 4 个任务在并发上限为 2 时全部执行，峰值同时运行数为 2。
- 抓取、调度、配置与 Web UI 相关回归：`51 passed`。
- 完整 gate：`bash scripts/release_check.sh` -> `1349 passed`，并通过 schema/API 契约、双前端启动、演示数据、健康检查、smoke 与发布制品验证。
