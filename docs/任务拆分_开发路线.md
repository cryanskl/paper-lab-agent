# 任务拆分与开发路线 · 等离子体文献系统

配套：`PRD_等离子体文献系统.md`（范围）、`接口设计文档.md`（API 真理来源）、`schema.sql`（数据模型真理来源）、`CLAUDE.md`（编码规则）。

## 怎么用这份清单（vibe coding 工作法）

- **一次只做一个任务**：把单个任务连同三份文档喂给 AI，做完再做下一个，别让它一口气写完几个阶段。
- **验收标准（AC）就是"做完"的定义**：AC 没全过 = 没做完，让 agent 继续改，不要进入下一个任务。
- **每个任务结束都要能本地起服务验证**：宁可任务切得小，也要保证可运行、可回滚。
- 任务按依赖顺序排列，`依赖` 列标了前置任务。

## 建议的两条"walking skeleton"

为了不每次都等抓取，准备少量已知样例端到端试跑：

- **检索链路**：手工塞 3–5 条真实 DOI（白名单期刊里的）进 `papers`，先把 T1.7 检索与 T1.8 前端跑通，再回头接 T1.2–T1.5 抓取。
- **理解链路**：准备 1 篇本地 PDF（最好是开放获取、含明确反应表的低温等离子体论文），贯穿 T2–T4 验证解析/翻译/抽取。
