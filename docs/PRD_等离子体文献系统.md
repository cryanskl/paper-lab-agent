## 0. 文档目的

本文档定义等离子体文献检索与理解系统 V1 的产品范围、用户流程、功能需求、数据边界、接口约束、验收标准和阶段路线。开发时以本文档描述的产品行为为目标，以 `接口设计文档.md` 作为 API 真理来源，以 `schema.sql` 作为数据模型真理来源，以 `任务拆分_开发路线.md` 作为实施顺序和验收拆分来源。

V1 必须保持 local-first：默认在本地部署、本地数据库、本地文件存储中完成文献元数据沉淀、PDF 导入、解析、翻译、RAG 与化学库抽取。不引入账号体系、云同步、团队协作、自动推荐、默认分类分组或任何未在路线文档中要求的扩展能力。

## 1. 背景与问题

公司业务聚焦低温等离子体相关仿真。仿真工程师在做算法测试、工艺建模或反应机理验证时，经常需要从论文中获取可复用的化学库、反应集、速率系数、电子碰撞截面、实验条件和模型假设。这些信息通常散落在论文正文、表格、附录和引用的数据库中，人工检索与整理成本高，且难以形成可复用资产。

当前工作流的主要问题是：

- **发现不稳定**：通用搜索或大模型回答可能混入不相关期刊、不相关主题或旧资料，难以稳定覆盖低温等离子体白名单期刊。
- **更新不及时**：人工周期性检索容易遗漏新发表文献；通用模型也受训练数据和搜索工具覆盖限制。
- **全文获取不可控**：部分论文闭源或需要机构访问，系统不能绕过付费墙、验证码、访问控制或站点条款。
- **理解结果不可追溯**：翻译、问答、反应抽取如果没有原文引用和人工复核，不能直接用于仿真输入。
- **知识沉淀不足**：一次调研得到的文献、段落、问答和反应数据没有进入统一本地资产库，后续项目重复劳动多。

本系统的核心策略是把“发现文献”和“理解文献”分层：发现层用确定性的学术元数据 API、期刊白名单、ISSN、关键词和日期增量抓取来保证范围可控；理解层在用户合法获取或上传 PDF 后，再用 GROBID、翻译、RAG 和抽取能力帮助理解内容。

## 2. 产品目标与非目标

### 2.1 产品目标

- **G1 本地文献索引**：将 1990 年至今的白名单期刊元数据沉淀到本地 SQLite 数据库，支持关键词、期刊、分类、日期和 OA 状态检索。
- **G2 确定性发现链路**：使用 ISSN、关键词、日期窗口和 DOI 去重构建可追溯抓取流程，不让大模型决定文献是否存在或是否被发现。
- **G3 合规全文入口**：只自动补全合法 OA 链接；闭源全文由用户通过授权渠道人工获取后导入。
- **G4 文献理解资产化**：对导入 PDF 建立结构化章节、双语翻译、RAG 分块和问答引用，使文献理解结果可复查、可复用。
- **G5 化学库交付闭环**：从文献中抽取反应集和截面信息，保留出处、置信度和人工复核状态；只有全部复核通过后才允许导出仿真输入。
- **G6 可分阶段演示**：阶段 1 跑通后即可独立演示“白名单抓取 → 检索 → OA 跳转”；后续阶段逐步增加导入解析、RAG 和化学库能力。

### 2.2 非目标

- 不自动绕过付费墙、验证码、登录、robots 限制或站点条款获取全文。
- 不保存用户密码，不实现机构账号代登录。
- 不做通用 Zotero / EndNote 替代品，不覆盖任意学科文献管理场景。
- 不做云端同步、团队空间、权限系统或多用户协作。
- 不承诺自动复现实验或论文 benchmark；Experiment Lab 仅可作为解释与 toy simulation 支撑。
- 不把模型抽取的速率系数、截面或反应式未经人工复核直接用于仿真。
- 不默认自动分类分组、自动刷新、自动推荐或自动导出；未被用户触发或路线文档要求的行为不进入 V1。

## 3. 用户与使用场景

### 3.1 目标用户

| 角色 | 核心任务 | 成功标准 |
| --- | --- | --- |
| 仿真工程师 | 查找低温等离子体论文，提取反应集、速率系数和截面数据 | 能快速定位论文，复核后导出可用于仿真的输入 |
| 研发人员 | 阅读、翻译、问答和理解领域论文 | 能获得带原文引用的回答和可对照的中英内容 |
| 系统维护者 | 维护期刊白名单、关键词、抓取任务和分类体系 | 抓取可追溯，配置可调整，异常可定位 |

### 3.2 典型场景

1. 仿真工程师希望找 “Ar/O2 ICP chemistry” 相关论文。
2. 系统维护者确保白名单期刊和关键词已启用，并按周或手动触发抓取。
3. 系统从 OpenAlex / Crossref / arXiv 拉取元数据，按 ISSN、日期和关键词过滤，用 DOI 去重入库，并通过 Unpaywall 补合法 OA 链接。
4. 工程师在检索界面按关键词、期刊、日期、分类或 OA 状态筛选论文。
5. 对有 OA PDF 的论文，工程师跳转下载；对闭源论文，工程师通过机构或图书馆等授权渠道获取。
6. 工程师上传 PDF，系统按哈希去重并关联已有 `papers` 元数据。
7. 系统解析章节、生成中英对照翻译，并按章节建立 RAG 分块。
8. 研发人员提问，系统返回答案与来源段落引用。
9. 工程师触发化学库抽取，系统生成待复核反应集。
10. 工程师逐条复核和修正反应，全部通过后导出 LXCat/BOLSIG+ 兼容文本或结构化 JSON。

## 4. 总体方案

系统采用两层异步解耦架构。

### 4.1 确定性检索层

确定性检索层负责发现和维护文献元数据。输入为期刊白名单、ISSN、关键词、日期窗口和抓取周期；处理流程为学术 API 查询、关键词过滤、DOI 去重、OA 链接补全和任务日志记录；输出为 `journals`、`papers`、`crawl_jobs`、`categories`、`paper_categories` 等本地数据。

该层的关键原则是：大模型不负责“发现文献”。模型最多参与后续分类，不参与期刊范围、文献存在性和 DOI 去重判断。

### 4.2 大模型理解层

大模型理解层负责用户已导入全文后的解析、翻译、问答和结构化抽取。入口是 `documents` 中的 PDF 文件；处理流程为 GROBID 解析章节、公式掩码翻译、按章节分块与向量化、RAG 查询、化学库抽取和人工复核；输出为 `sections`、`translations`、`chunks`、`reaction_sets`、`reactions` 等本地数据。

该层的关键原则是：所有生成结果必须可追溯。RAG 回答必须返回来源段落；化学库抽取必须保留出处、置信度和人工复核状态。

### 4.3 异步任务约定

抓取、解析、翻译、索引和抽取都属于耗时操作，接口必须立即返回任务或资源状态，前端通过状态字段或任务查询轮询结果。V1 不要求实时推送。

### 4.4 技术边界

建议技术栈与接口文档保持一致：FastAPI、SQLite、APScheduler、GROBID、Chroma 或 FAISS，前端起步使用 Streamlit。所有默认测试必须可离线、确定性运行；真实网络和真实模型检查必须作为单独集成测试。

## 5. 功能需求 · 阶段 1 确定性检索层

阶段 1 对应开发路线中的 F1-F5 与 T1.1-T1.8。该阶段完成后，系统应能从空库初始化开始，维护期刊白名单，抓取白名单期刊元数据，补全合法 OA 链接，并通过最小前端检索文献。阶段 1 是 V1 的第一个可独立演示版本。

### 5.1 期刊白名单管理

**目标**：维护确定性检索层的范围边界。只有白名单中的 active 期刊参与自动抓取。

| 编号 | 需求 | 优先级 | 数据/API 对齐 | 验收标准 |
| --- | --- | --- | --- | --- |
| P1-J1 | 系统内置 6 本低温等离子体相关种子期刊 | P0 | `journals`；`GET /journals` | 初始化数据库后能列出 6 本期刊 |
| P1-J2 | 支持新增期刊，字段包括名称、出版社、平台、URL、print/electronic ISSN、关键词、起始年份 | P0 | `POST /journals` | 新增后可在列表与详情中查询 |
| P1-J3 | 支持更新关键词、年份范围和启停状态 | P0 | `PUT /journals/{id}` | 更新后后续抓取使用新配置 |
| P1-J4 | 删除采用软删，置 `active=0`，不物理删除历史数据 | P0 | `DELETE /journals/{id}` | 软删后默认抓取不再包含该期刊 |
| P1-J5 | 支持按 `active=1` 过滤列表 | P0 | `GET /journals?active=1` | 只返回启用期刊 |

**约束**：

- ISSN 是抓取范围控制的核心字段，抓取客户端必须优先使用 ISSN 精确定位期刊。
- `keywords` 以 JSON 数组存储，关键词逻辑用于入库前过滤，不用于动态生成未授权站点抓取。
- `year_from` 默认 1990，`year_to=NULL` 表示持续至今。

### 5.2 学术元数据抓取

**目标**：按期刊 ISSN、日期窗口和关键词从学术元数据 API 拉取文献，并写入本地 `papers`。

| 编号 | 需求 | 优先级 | 数据/API 对齐 | 验收标准 |
| --- | --- | --- | --- | --- |
| P1-C1 | 支持 OpenAlex/Crossref 客户端，按 ISSN 和日期范围拉取 works | P0 | `POST /crawl/run` | 给定 ISSN 和日期能获得归一化论文列表 |
| P1-C2 | 归一化字段至少包括 DOI、标题、摘要、作者、期刊、发表日期、落地页 URL、来源 API、原始元数据 | P0 | `papers` | 入库记录字段完整，原始响应可重处理 |
| P1-C3 | 抓取前后记录 `crawl_jobs`，包含期刊、周期、日期范围、状态、found/new/error、开始/结束时间 | P0 | `crawl_jobs`；`GET /crawl/jobs` | 每次抓取都有可追溯任务记录 |
| P1-C4 | 使用 DOI 去重，重复抓取同 DOI 更新已有记录，不新增重复行 | P0 | `papers.doi UNIQUE` | 同 DOI 多次抓取只有一条记录 |
| P1-C5 | 对无 DOI 文献允许入库，但必须保留来源 URL 和原始元数据，降低误合并风险 | P1 | `papers.doi` 可空 | 无 DOI 文献不阻塞抓取任务 |
| P1-C6 | 支持关键词过滤；不命中期刊关键词的文献不入库 | P0 | `journals.keywords` | 抽样验证无关键词命中的文献被过滤 |
| P1-C7 | 客户端需要设置 polite pool / mailto、限流和重试策略 | P0 | settings / external clients | API 限流时任务失败原因清晰可见 |

**增量规则**：

- 手动触发可显式传 `date_from` 和 `date_to`。
- 未传日期时，以该期刊最近一次成功 `crawl_jobs.date_to` 作为下次 `date_from` 的依据。
- 首次抓取可按期刊 `year_from` 起算，但实际任务可通过较小日期窗口控制，避免一次性请求过大。

### 5.3 OA 链接补全

**目标**：最大化自动发现合法开放获取全文链接，同时不绕过访问控制。

| 编号 | 需求 | 优先级 | 数据/API 对齐 | 验收标准 |
| --- | --- | --- | --- | --- |
| P1-O1 | 对有 DOI 的论文调用 Unpaywall 补全 `oa_status` 和 `oa_pdf_url` | P0 | `papers.oa_status`、`papers.oa_pdf_url` | 给定 DOI 可写入 OA 状态与 PDF 链接 |
| P1-O2 | 对无 OA 链接或请求失败的论文，状态置为 `unknown` 或保留失败原因，不编造链接 | P0 | `papers.raw_metadata` / job error | 无合法链接时字段为空或 unknown |
| P1-O3 | 支持用户对单篇论文重新解析 OA 链接 | P1 | `POST /papers/{id}/resolve-oa` | 重新解析后更新 OA 字段 |

**合规约束**：

- 只自动下载或跳转直接可访问的 OA PDF 或 allowlisted 来源。
- 不绕过付费墙、验证码、登录、访问控制、robots 限制或站点条款。
- 若需要用户授权会话但当前不可用，只记录失败原因和元数据链接。

### 5.4 定时调度

**目标**：让文献元数据保持可控更新，但不要求实时。

| 编号 | 需求 | 优先级 | 数据/API 对齐 | 验收标准 |
| --- | --- | --- | --- | --- |
| P1-S1 | 支持 daily / weekly / monthly 抓取周期配置 | P0 | APScheduler；`crawl_jobs.period` | 配置周期能自动创建 crawl job |
| P1-S2 | 定时任务与手动抓取调用同一编排逻辑 | P0 | `POST /crawl/run` 内部服务 | 手动和定时记录结构一致 |
| P1-S3 | 抓取失败不影响已有检索数据；失败原因写入 `crawl_jobs.error` | P0 | `crawl_jobs.status/error` | API 失败后历史数据仍可检索 |

### 5.5 文献检索

**目标**：为工程师提供本地文献库检索能力，结果包含关键元数据、分类和 OA 跳转。

| 编号 | 需求 | 优先级 | 数据/API 对齐 | 验收标准 |
| --- | --- | --- | --- | --- |
| P1-P1 | 支持标题与摘要全文检索，使用 SQLite FTS5 | P0 | `papers_fts`；`GET /papers?q=` | 输入关键词返回相关论文 |
| P1-P2 | 支持分类、期刊、年份范围、OA-only 过滤 | P0 | `GET /papers` query | 多条件组合过滤正确 |
| P1-P3 | 支持 `date_desc` 默认排序和 `relevance` 排序 | P0 | `GET /papers?sort=` | 排序结果符合参数语义 |
| P1-P4 | 列表响应使用统一分页结构 | P0 | `{items,total,page,page_size}` | 分页字段完整且数量正确 |
| P1-P5 | 结果项展示 DOI、标题、期刊、发表日期、OA 状态、OA PDF URL、落地页 URL、分类 | P0 | `papers` + `paper_categories` | 前端列表可以直接展示和跳转 |
| P1-P6 | 文献详情接口返回单篇论文的完整元数据 | P0 | `GET /papers/{id}` | 详情页可用于核对原始信息 |

### 5.6 分类体系

**目标**：提供领域主题 taxonomy，用于筛选和后续 LLM 分类。

| 编号 | 需求 | 优先级 | 数据/API 对齐 | 验收标准 |
| --- | --- | --- | --- | --- |
| P1-T1 | 初始化 7 个种子分类：放电与等离子体源、等离子体化学、鞘层与边界、输运与扩散、等离子体诊断、仿真方法、截面与速率数据 | P0 | `categories` | 初始化后分类可查询 |
| P1-T2 | 支持分类列表，保留 `parent_id` 扩展层级能力 | P0 | `GET /categories` | 返回 slug/name/description/parent_id |
| P1-T3 | 支持人工覆盖论文分类，为后续 LLM 分类打基础 | P1 | `PUT /papers/{id}/categories` | 覆盖后 `method=manual` |

### 5.7 最小前端

**目标**：提供一个可演示的检索入口，不做复杂工作台。

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| P1-U1 | Streamlit 页面支持关键词输入、期刊筛选、日期筛选、OA-only 开关 | P0 | 用户能组合条件检索 |
| P1-U2 | 检索结果以列表展示标题、期刊、日期、摘要片段、OA 状态和链接 | P0 | 结果可读且可跳转 OA/落地页 |
| P1-U3 | 空结果、抓取失败、API 错误需要显示明确错误或空态 | P0 | 不出现无解释的空白页 |

### 5.8 阶段 1 里程碑验收

从空库开始：

1. 用 `schema.sql` 初始化 SQLite 数据库。
2. 确认可查询 6 本种子期刊和 7 个种子分类。
3. 手动触发一次 `/crawl/run`，至少针对一个 active 期刊和一个短日期窗口。
4. 抓取任务写入 `crawl_jobs`，状态、found/new/error 可查。
5. 命中文献写入 `papers`，重复 DOI 不产生重复行。
6. 对有 DOI 文献补全 OA 状态和合法 OA PDF URL。
7. `GET /papers` 可按关键词、期刊、日期和 OA-only 检索。
8. Streamlit 前端可展示检索结果并跳转 OA 链接。

## 6. 功能需求 · 阶段 2 导入 / 解析 / 翻译

阶段 2 对应开发路线中的 F7-F9 与 T2.1-T2.5。该阶段的目标是把用户合法获取的 PDF 变成本地可理解资产：可去重、可关联论文元数据、可解析章节、可生成公式不乱的中英对照翻译。

### 6.1 PDF 导入

| 编号 | 需求 | 优先级 | 数据/API 对齐 | 验收标准 |
| --- | --- | --- | --- | --- |
| P2-D1 | 支持上传 PDF，multipart 字段为 `file`，可选 `paper_id` | P1 | `POST /documents`；`documents` | 上传后写入 documents |
| P2-D2 | 使用 `file_hash` 去重；重复上传返回已有资源，不重复存储 | P1 | `documents.file_hash UNIQUE` | 相同 PDF 上传两次只保留一条记录 |
| P2-D3 | 支持导入未入索引的 PDF，`paper_id` 可为空 | P1 | `documents.paper_id` 可空 | 无 paper_id 不阻塞上传 |
| P2-D4 | 保存原始文件名、文件路径、页数和创建时间 | P1 | `documents.original_name/file_path/num_pages` | 详情接口可查询这些字段 |
| P2-D5 | 文档列表和详情显示解析状态 | P1 | `GET /documents`、`GET /documents/{id}` | 用户能看到 uploaded/parsing/parsed/failed |

### 6.2 GROBID 解析

| 编号 | 需求 | 优先级 | 数据/API 对齐 | 验收标准 |
| --- | --- | --- | --- | --- |
| P2-G1 | 系统能连接本地 GROBID 服务并做健康检查 | P1 | settings / GROBID client | 本地 POST PDF 可拿到 TEI |
| P2-G2 | 用户触发解析后，文档状态从 uploaded 进入 parsing，完成后为 parsed，失败为 failed | P1 | `POST /documents/{id}/parse`；`documents.parse_status` | 状态流转可查 |

## 9. 数据模型要求

数据库以 `schema.sql` 为真理来源。PRD 不重复定义 SQL 细节，但产品行为必须符合以下数据边界。

| 数据域 | 表 | 产品含义 | 关键约束 |
| --- | --- | --- | --- |
| 期刊白名单 | `journals` | 决定确定性抓取范围 | active 控制启停；ISSN 控制期刊定位；keywords 控制主题过滤 |
| 文献元数据 | `papers`、`papers_fts` | 本地可检索文献索引 | DOI 去重；标题和摘要进入 FTS5；全文不存入 papers |
| 分类 | `categories`、`paper_categories` | 主题 taxonomy 与论文分类 | 支持多分类；manual 覆盖优先于 auto |
| 抓取任务 | `crawl_jobs` | 抓取可追溯与增量依据 | success 的 date_to 可作为下次增量起点 |
| PDF 文档 | `documents` | 用户导入全文入口 | file_hash 去重；paper_id 可空；parse_status 表示解析状态 |
| 章节结构 | `sections` | GROBID 解析出的结构化文本 | 保留 parent_id、seq、section_type，支持按章节分块 |
| 翻译 | `translations` | 双语对照产物记录 | status 表示翻译状态；output_path 指向本地文件 |
| RAG 分块 | `chunks` | 本地问答证据单元 | vector_id 映射外部向量库；回答引用必须能回查 chunk |
| 化学库 | `reaction_sets`、`reactions` | 反应集与逐条反应资产 | reaction_set 导出前要求所有 reactions verified=1 |

### 9.1 数据保留与文件存储

- SQLite 保存结构化元数据、状态、路径、引用和映射。
- PDF、TEI、翻译产物和导出文件保存在本地文件系统，数据库保存路径。
- 原始 API 响应保存在 `papers.raw_metadata`，用于审计和重处理。
- 不保存用户密码、机构账号或绕过访问控制所需凭据。

### 9.2 数据质量约束

- DOI 命中时以 DOI 为主要去重键。
- 无 DOI 文献不得与其他无 DOI 文献自动合并，除非后续实现了明确且可测试的合并规则。
- 速率系数、截面、反应式等数值型交付数据必须保留原文表达，不自动单位换算。
- 所有模型生成的分类、回答和抽取结果都必须保留来源或方法字段，便于人工判断可信度。

## 10. API 与交互约定

API 以 `接口设计文档.md` 为真理来源，PRD 层面的产品约定如下。

### 10.1 通用 API 约定

- 基址为 `/api/v1`。
- JSON 接口使用 `application/json`，文件上传使用 multipart。
- 列表统一分页：`{ "items": [...], "total": <int>, "page": <int>, "page_size": <int> }`。
- 错误统一为 `{ "error": { "code": "...", "message": "..." } }`，并配合 400、404、409、422、500 等语义化状态码。
- 耗时操作立即返回 pending 状态或 job id，不阻塞等待任务完成。
- 起步阶段不做鉴权；上线前若需要鉴权，应在网关或中间件统一添加，不改变核心本地工作流。

### 10.2 状态与错误体验

- 抓取、解析、翻译、索引、抽取都必须有用户可见状态。
- 失败信息需要能支持下一步处理，例如“API 限流”“GROBID 不可用”“PDF 已存在”“证据不足无法回答”“未全部复核不可导出”。
- 前端不得把失败状态展示成空白页或成功结果。

### 10.3 前端范围

V1 前端以可演示和可操作为目标，不追求复杂管理后台。阶段 1 使用 Streamlit 完成检索界面；后续阶段依次增加上传、解析查看、翻译查看、问答、反应集复核和导出。前端不得引入未在 PRD 中定义的账号、云同步、团队协作或自动推荐功能。

## 11. 下载、访问与合规政策

系统必须遵循以下下载与访问边界：

- 自动下载仅限直接可访问 PDF 或 allowlisted 来源。
- Unpaywall 返回的 OA 链接可以作为合法全文入口，但仍需处理链接失效、非 PDF 或访问失败。
- 不绕过付费墙、验证码、登录、访问控制、robots 限制或站点条款。
- 如果来源需要登录，而当前没有用户授权会话，系统只记录失败原因和元数据链接。
- 不存储用户密码。
- 闭源全文由用户自行通过机构访问、图书馆、馆际互借或其他合法渠道获取后再上传。

## 12. RAG 与生成式回答规则

- RAG 回答必须引用论文标题或 paper id，并给出 segment/chunk/section 级来源。
- 检索证据不足时，回答应明确说明证据不足，不得补全或猜测。
- 默认测试必须使用 fixture 和 fake model adapter，避免测试依赖真实模型的不稳定输出。
- 真实模型和真实网络检查必须作为单独集成测试，不进入默认测试门禁。
- 翻译、问答、分类和抽取结果都应被视为辅助信息，关键工程数据以人工复核为准。

## 13. 非功能需求

| 类别 | 要求 | 验收方式 |
| --- | --- | --- |
| 本地优先 | 默认可在单机本地运行，核心数据保存在 SQLite 和本地文件系统 | 断网时仍可检索已有数据、查看已导入文档 |
| 可追溯 | 抓取任务、来源 API、原始元数据、RAG 引用、反应出处都可回查 | 抽样追溯一条结果到原始来源 |
| 确定性测试 | 默认测试无网络、无真实模型依赖 | CI/本地默认 test 通过 |
| 合规 | 不绕过访问控制，不存密码，不伪造 OA 链接 | 代码与测试覆盖失败路径 |
| 可恢复 | 抓取或解析失败不破坏已有数据 | 失败后历史检索仍可用 |
| 可演示 | 每阶段都有可独立演示的 walking skeleton | 阶段验收脚本或手工流程可跑通 |
| 最小实现 | 不添加 PRD 外功能 | review 时检查无账号/云同步/自动推荐等扩展 |

## 15. 验收标准

### 15.1 全局验收

- PRD、接口文档、schema 和开发路线的模块命名一致。
- 所有默认测试确定性、无网络、无真实模型依赖。
- 文档中没有承诺未实现的云端、多用户、自动推荐或 benchmark 复现能力。
- 下载行为符合合规政策。
- RAG 和化学库结果具备可追溯来源。

### 15.2 阶段验收

- 阶段 0：`uvicorn` 能启动；`GET /health` 返回 200；数据库不存在时可用 `schema.sql` 初始化；能查到 6 本种子期刊。
- 阶段 1：从空库触发抓取后，`crawl_jobs`、`papers`、OA 字段和前端检索链路跑通。
- 阶段 2：上传合法 PDF 后，哈希去重、GROBID 解析、章节入库和公式保护翻译跑通。
- 阶段 3：对已解析文档建立 chunks 和向量索引，RAG 回答带 chunk/section 来源；证据不足时明确说明。
- 阶段 4：抽取 pending 反应集，未全复核导出返回 409；全复核后可导出 JSON 或 LXCat/BOLSIG+ 兼容文本。

## 16. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 学术 API 限流或策略变化 | 抓取任务失败或变慢 | 设置 polite pool / mailto、限流、重试、错误记录，并保留多 API 备援 |
| OA 覆盖不足 | 仍需大量人工下载 | 明确人工获取为既定环节，系统只最大化合法 OA 链接补全 |
| ISSN 或关键词配置错误 | 抓取范围偏差 | 上线前核对种子期刊；白名单支持人工维护 |
| GROBID 解析复杂排版失败 | 下游翻译/RAG/抽取质量下降 | 标记 failed，保留 TEI/错误，允许人工补救或重跑 |
| 模型分类或抽取错误 | 搜索筛选或仿真输入受影响 | 分类支持人工覆盖；化学库必须逐条复核后导出 |
| RAG 幻觉 | 研发误读文献 | 强制引用来源；证据不足时明确拒答 |
| 默认测试依赖外部服务 | CI 不稳定 | 使用 fixture 和 fake adapter；真实网络/模型放入集成测试 |
