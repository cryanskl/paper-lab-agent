## 0. 文档目的

本文档定义等离子体文献检索与理解系统 V1 的产品范围、用户流程、功能需求、数据边界、接口约束、验收标准和阶段路线。开发时以本文档描述的产品行为为目标，以 `接口设计文档.md` 作为 API 真理来源，以 `schema.sql` 作为数据模型真理来源，以 `任务拆分_开发路线.md` 作为实施顺序和验收拆分来源。

V1 必须保持 local-first：默认在本地部署、本地数据库、本地文件存储中完成文献元数据沉淀、PDF 导入、解析、翻译、RAG 与化学库抽取。不引入账号体系、云同步、团队协作、自动推荐、默认分类分组或任何未在路线文档中要求的扩展能力。

## 1. 背景与问题

公司业务聚焦低温等离子体相关仿真。仿真工程师在做算法测试、工艺建模或反应机理验证时，经常需要从论文中获取可复用的化学库、反应集、速率系数、电子碰撞截面、实验条件和模型假设。这些信息通常散落在论文正文、表格、附录和引用的数据库中，人工检索与整理成本高，且难以形成可复用资产。

当前工作流的主要问题是：

- **发现不稳定**：通用搜索或大模型回答可能混入不相关期刊、不相关主题或旧资料，难以稳定覆盖低温等离子体白名单期刊。
- **更新不及时**：人工周期性检索容易遗漏新发表文献；通用模型也受训练数据和搜索工具覆盖限制。
- **全文获取不可控**：部分论文闭源或需要机构访问，系统不能绕过付费墙、验证码、访问控制或站点条款。
- **理解结果不可追溯**：翻译、问答、反应抽取如果没有原文引用和人工复核，不能直接用于仿真输入。
- **知识沉淀不足**：一次调研得到的文献、段落、问答和反应数据没有进入统一本地资产库，后续项目重复劳动多。

本系统的核心策略是把“发现文献”和“理解文献”分层：发现层用确定性的学术元数据 API、期刊白名单、ISSN、关键词和日期增量抓取来保证范围可控；理解层在用户合法获取或上传 PDF 后，再用 GROBID、翻译、RAG 和抽取能力帮助理解内容。

## 2. 产品目标与非目标

### 2.1 产品目标

- **G1 本地文献索引**：将 1990 年至今的白名单期刊元数据沉淀到本地 SQLite 数据库，支持关键词、期刊、分类、日期和 OA 状态检索。
- **G2 确定性发现链路**：使用 ISSN、关键词、日期窗口和 DOI 去重构建可追溯抓取流程，不让大模型决定文献是否存在或是否被发现。
- **G3 合规全文入口**：只自动补全合法 OA 链接；闭源全文由用户通过授权渠道人工获取后导入。
- **G4 文献理解资产化**：对导入 PDF 建立结构化章节、双语翻译、RAG 分块和问答引用，使文献理解结果可复查、可复用。
- **G5 化学库交付闭环**：从文献中抽取反应集和截面信息，保留出处、置信度和人工复核状态；只有全部复核通过后才允许导出仿真输入。
- **G6 可分阶段演示**：阶段 1 跑通后即可独立演示“白名单抓取 → 检索 → OA 跳转”；后续阶段逐步增加导入解析、RAG 和化学库能力。

### 2.2 非目标

- 不自动绕过付费墙、验证码、登录、robots 限制或站点条款获取全文。
- 不保存用户密码，不实现机构账号代登录。
- 不做通用 Zotero / EndNote 替代品，不覆盖任意学科文献管理场景。
- 不做云端同步、团队空间、权限系统或多用户协作。
- 不承诺自动复现实验或论文 benchmark；Experiment Lab 仅可作为解释与 toy simulation 支撑。
- 不把模型抽取的速率系数、截面或反应式未经人工复核直接用于仿真。
- 不默认自动分类分组、自动刷新、自动推荐或自动导出；未被用户触发或路线文档要求的行为不进入 V1。

## 3. 用户与使用场景

### 3.1 目标用户

| 角色 | 核心任务 | 成功标准 |
| --- | --- | --- |
| 仿真工程师 | 查找低温等离子体论文，提取反应集、速率系数和截面数据 | 能快速定位论文，复核后导出可用于仿真的输入 |
| 研发人员 | 阅读、翻译、问答和理解领域论文 | 能获得带原文引用的回答和可对照的中英内容 |
| 系统维护者 | 维护期刊白名单、关键词、抓取任务和分类体系 | 抓取可追溯，配置可调整，异常可定位 |

### 3.2 典型场景

1. 仿真工程师希望找 “Ar/O2 ICP chemistry” 相关论文。
2. 系统维护者确保白名单期刊和关键词已启用，并按周或手动触发抓取。
3. 系统从 OpenAlex / Crossref / arXiv 拉取元数据，按 ISSN、日期和关键词过滤，用 DOI 去重入库，并通过 Unpaywall 补合法 OA 链接。
4. 工程师在检索界面按关键词、期刊、日期、分类或 OA 状态筛选论文。
5. 对有 OA PDF 的论文，工程师跳转下载；对闭源论文，工程师通过机构或图书馆等授权渠道获取。
6. 工程师上传 PDF，系统按哈希去重并关联已有 `papers` 元数据。
7. 系统解析章节、生成中英对照翻译，并按章节建立 RAG 分块。
8. 研发人员提问，系统返回答案与来源段落引用。
9. 工程师触发化学库抽取，系统生成待复核反应集。
10. 工程师逐条复核和修正反应，全部通过后导出 LXCat/BOLSIG+ 兼容文本或结构化 JSON。

## 4. 总体方案

系统采用两层异步解耦架构。

### 4.1 确定性检索层

确定性检索层负责发现和维护文献元数据。输入为期刊白名单、ISSN、关键词、日期窗口和抓取周期；处理流程为学术 API 查询、关键词过滤、DOI 去重、OA 链接补全和任务日志记录；输出为 `journals`、`papers`、`crawl_jobs`、`categories`、`paper_categories` 等本地数据。

该层的关键原则是：大模型不负责“发现文献”。模型最多参与后续分类，不参与期刊范围、文献存在性和 DOI 去重判断。

### 4.2 大模型理解层

大模型理解层负责用户已导入全文后的解析、翻译、问答和结构化抽取。入口是 `documents` 中的 PDF 文件；处理流程为 GROBID 解析章节、公式掩码翻译、按章节分块与向量化、RAG 查询、化学库抽取和人工复核；输出为 `sections`、`translations`、`chunks`、`reaction_sets`、`reactions` 等本地数据。

该层的关键原则是：所有生成结果必须可追溯。RAG 回答必须返回来源段落；化学库抽取必须保留出处、置信度和人工复核状态。

### 4.3 异步任务约定

抓取、解析、翻译、索引和抽取都属于耗时操作，接口必须立即返回任务或资源状态，前端通过状态字段或任务查询轮询结果。V1 不要求实时推送。

### 4.4 技术边界

建议技术栈与接口文档保持一致：FastAPI、SQLite、APScheduler、GROBID、Chroma 或 FAISS，前端起步使用 Streamlit。所有默认测试必须可离线、确定性运行；真实网络和真实模型检查必须作为单独集成测试。
